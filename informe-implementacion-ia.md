## 2. Implementación de IA en el Departamento de Informática

### 2.1 IA para Desarrollo de Software: GitHub Copilot y Asistentes de Código

#### Finalidad y Funcionamiento

El departamento de informática de TechnoComponents implementará **GitHub Copilot Enterprise** junto con **herramientas de IA generativa para código** como asistente de programación para todo el equipo de desarrollo de software.

**¿Quién la usaría?**
- Los 15 desarrolladores del equipo de software interno
- Los 8 administradores de bases de datos
- Los 5 especialistas en desarrollo web
- Los 7 técnicos de soporte y DevOps

**¿Cómo funciona?**
La IA se integra directamente en los entornos de desarrollo (Visual Studio Code, IntelliJ IDEA, etc.) y proporciona:

1. **Autocompletado inteligente**: Sugiere líneas de código completas basándose en el contexto del proyecto.
2. **Generación de funciones**: A partir de comentarios en lenguaje natural, genera bloques de código funcionales.
3. **Documentación automática**: Crea documentación técnica y comentarios para el código existente.
4. **Detección de errores**: Identifica bugs potenciales y sugiere correcciones.
5. **Conversión de código**: Ayuda a migrar código entre diferentes lenguajes de programación.
6. **Consultas en lenguaje natural**: Permite hacer preguntas sobre el código y obtener explicaciones.

#### Tipo de IA

**IA Generativa** basada en modelos de lenguaje grande (LLM - Large Language Models) entrenados con millones de repositorios de código. Utiliza arquitecturas transformer que procesan el contexto del código para generar sugerencias coherentes y relevantes.

#### Beneficios Esperados

| Beneficio | Impacto Estimado |
|-----------|------------------|
| **Aumento de productividad** | 40% más líneas de código útil por desarrollador |
| **Reducción de tiempo en tareas repetitivas** | 55% menos tiempo en código boilerplate |
| **Mejora en la calidad del código** | 30% menos bugs en producción |
| **Aceleración del onboarding** | Nuevos desarrolladores productivos en 2 semanas vs 6 semanas |
| **Ahorro económico anual** | Aproximadamente 180.000€ en horas de desarrollo |

## 3. Implementación de IA en Otros Departamentos

### 3.1 Departamento de Control de Calidad: IA de Visión Artificial para Inspección

#### Finalidad y Funcionamiento

Implementación de un **sistema de visión artificial con Deep Learning** para la inspección automatizada de componentes electrónicos en las líneas de producción.

**¿Quién la usaría?**
- Los 45 empleados de control de calidad
- Supervisores de línea de producción
- Ingenieros de calidad

**¿Cómo funciona?**

El sistema utiliza cámaras de alta resolución instaladas en puntos estratégicos de la línea de producción que capturan imágenes de cada componente fabricado. Estas imágenes son procesadas en tiempo real por una red neuronal convolucional (CNN) que:

1. **Detecta defectos visuales**: Grietas, soldaduras defectuosas, componentes mal alineados.
2. **Clasifica el tipo de defecto**: Categoriza automáticamente el problema detectado.
3. **Toma decisiones en tiempo real**: Acepta o rechaza piezas automáticamente.
4. **Genera reportes**: Documenta estadísticas de defectos para análisis posterior.

#### Tipo de IA

**IA de Clasificación y Detección** basada en redes neuronales convolucionales (CNN) para visión por computadora. Específicamente, se utiliza una arquitectura YOLO (You Only Look Once) optimizada para detección en tiempo real.

#### Beneficios Esperados

| Beneficio | Impacto Estimado |
|-----------|------------------|
| **Precisión en detección** | 99.7% vs 94% de inspección humana |
| **Velocidad de inspección** | 500 componentes/minuto vs 50 manual |
| **Reducción de productos defectuosos enviados** | 85% menos devoluciones |
| **Ahorro en costes de calidad** | 320.000€ anuales |
| **Reducción de reclamaciones de clientes** | 60% menos incidencias |

### 3.3 Departamento de Producción: IA Predictiva para Mantenimiento de Maquinaria

> **⚠️ NOTA IMPORTANTE: Esta IA será entrenada desde cero por la propia empresa**

#### Finalidad y Funcionamiento

Desarrollo e implementación de un **sistema de mantenimiento predictivo basado en Machine Learning** que anticipe fallos en la maquinaria de producción antes de que ocurran.

**¿Quién la usaría?**
- Los 180 empleados de producción
- Equipo de mantenimiento (15 técnicos)
- Supervisores de planta
- Dirección de operaciones

**¿Cómo funciona?**

El sistema recopila datos de sensores IoT instalados en las máquinas de producción:

1. **Recolección de datos**:
   - Temperatura de motores y componentes
   - Vibraciones
   - Consumo eléctrico
   - Presión hidráulica
   - Velocidad de operación
   - Horas de funcionamiento

2. **Procesamiento en tiempo real**:
   - Los datos se envían a una plataforma cloud
   - Se procesan y normalizan continuamente

3. **Predicción de fallos**:
   - El modelo ML analiza patrones anómalos
   - Predice probabilidad de fallo en diferentes horizontes temporales (24h, 7 días, 30 días)
   - Identifica qué componente específico fallará

4. **Alertas y recomendaciones**:
   - Genera alertas automáticas al equipo de mantenimiento
   - Sugiere acciones preventivas específicas
   - Programa intervenciones optimizando la producción

#### Tipo de IA

**IA Predictiva** basada en algoritmos de Machine Learning para series temporales y detección de anomalías.

## 4. Detalle del Entrenamiento de la IA de Mantenimiento Predictivo

### 4.1 Tipo de Entrenamiento: Aprendizaje Supervisado por Regresión

Para el sistema de mantenimiento predictivo, utilizaremos **Aprendizaje Supervisado por Regresión**, complementado con técnicas de **Detección de Anomalías**.

### 4.2 ¿Por qué Aprendizaje Supervisado por Regresión?

El objetivo principal es **predecir el tiempo restante hasta el fallo** de cada componente (RUL - Remaining Useful Life). Este es un problema de regresión porque:

- La variable objetivo es **continua** (número de horas/días hasta el fallo)
- Necesitamos predecir un **valor numérico específico**, no una categoría
- Los datos históricos incluyen el momento exacto de cada fallo registrado

### 4.3 Funcionamiento del Aprendizaje Supervisado por Regresión

#### Fase 1: Recolección y Preparación de Datos

```
┌─────────────────────────────────────────────────────────────┐
│                    DATOS DE ENTRADA                         │
├─────────────────────────────────────────────────────────────┤
│ • Lecturas de sensores (temperatura, vibración, presión)    │
│ • Registros históricos de mantenimiento                     │
│ • Datos de fallos anteriores con timestamps                 │
│ • Información de operación (carga, velocidad, ciclos)       │
│ • Condiciones ambientales (humedad, temperatura ambiente)   │
└─────────────────────────────────────────────────────────────┘
```

**Datos necesarios:**
- **Mínimo 2 años** de datos históricos de operación
- **Al menos 50-100 ejemplos de fallos** por tipo de máquina
- **Etiquetas precisas**: Cada registro debe estar etiquetado con el tiempo real hasta el siguiente fallo

#### Fase 2: Procesamiento y Características

Se crean **features (características)** a partir de los datos crudos:

| Tipo de Feature | Ejemplos |
|-----------------|----------|
| **Estadísticas básicas** | Media, desviación estándar, máximo, mínimo de cada sensor |
| **Características temporales** | Tendencias, tasas de cambio, patrones cíclicos |
| **Features de dominio** | Ratio de eficiencia energética, índice de desgaste |
| **Agregaciones temporales** | Promedios móviles de 1h, 24h, 7 días |

#### Fase 3: Entrenamiento del Modelo

```
┌─────────────────────────────────────────────────────────────┐
│              PROCESO DE ENTRENAMIENTO                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   DATOS DE ENTRADA          MODELO             SALIDA       │
│   (Features de sensores)    (Algoritmo)        (Predicción) │
│                                                             │
│   ┌─────────────────┐      ┌──────────┐      ┌───────────┐  │
│   │ Temperatura: 78°│      │          │      │           │  │
│   │ Vibración: 2.3  │  ──▶ │ Random   │  ──▶ │ RUL: 145  │  │
│   │ Presión: 4.2    │      │ Forest   │      │ horas     │  │
│   │ Horas uso: 8500 │      │ Regressor│      │           │  │
│   │ ...             │      │          │      │           │  │
│   └─────────────────┘      └──────────┘      └───────────┘  │
│                                                             │
│                            ▲                                │
│                            │                                │
│                    ┌───────┴───────┐                        │
│                    │ ETIQUETA REAL │                        │
│                    │ (Tiempo hasta │                        │
│                    │ fallo conocido│                        │
│                    │ = 142 horas)  │                        │
│                    └───────────────┘                        │
│                                                             │
│   El modelo ajusta sus parámetros para minimizar           │
│   la diferencia entre predicción (145h) y realidad (142h)  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**Algoritmos utilizados:**

1. **Random Forest Regressor**: Algoritmo principal por su robustez y capacidad de manejar múltiples variables.

2. **Gradient Boosting (XGBoost)**: Para comparar rendimiento y crear un ensemble.

3. **LSTM (Long Short-Term Memory)**: Red neuronal recurrente para capturar dependencias temporales largas.

#### Fase 4: Función de Pérdida y Optimización

En el aprendizaje supervisado por regresión, el modelo **minimiza una función de pérdida** que mide el error entre predicciones y valores reales.

**Función de pérdida utilizada: MSE (Mean Squared Error)**

```
MSE = (1/n) × Σ(y_real - y_predicho)²
```

Donde:
- `y_real` = Tiempo real hasta el fallo (etiqueta conocida)
- `y_predicho` = Predicción del modelo
- `n` = Número de ejemplos de entrenamiento

El algoritmo de optimización (Gradient Descent) ajusta los parámetros del modelo iterativamente para **minimizar el MSE**.

#### Fase 5: Validación y Evaluación

```
┌─────────────────────────────────────────────────────────────┐
│                 DIVISIÓN DE DATOS                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ████████████████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │
│  ◄─── 70% Entrenamiento ───►◄─ 15% Valid ─►◄── 15% Test ──►│
│                                                             │
│  • Entrenamiento: El modelo aprende los patrones           │
│  • Validación: Ajuste de hiperparámetros                   │
│  • Test: Evaluación final del rendimiento                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**Métricas de evaluación:**
- **RMSE (Root Mean Squared Error)**: Error promedio en la misma unidad que la predicción (horas)
- **MAE (Mean Absolute Error)**: Error absoluto promedio
- **R² (Coeficiente de determinación)**: Proporción de varianza explicada por el modelo
